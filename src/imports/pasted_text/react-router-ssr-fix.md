FIX ONLY THE REACT ROUTER SSR HYDRATION SCRIPT PLACEMENT — DO NOT CHANGE ANYTHING ELSE

Goal:
Correct the SSR/prerender hydration architecture so the React Router hydration data generated by StaticRouterProvider is available to the browser without placing its hydration <script> inside the React #root that is later hydrated.

IMPORTANT:
This is an isolated technical fix.
Do NOT change the site's design, content, routes, SEO metadata, images, service icons, favicon, OG image, typography, colors, or any unrelated code.

SERVER:

CLIENT:

Do not replace the SSR architecture.

==================================================
2. KEEP REACT ROUTER HYDRATION DATA ENABLED
==================================================

In src/entry-server.tsx, keep StaticRouterProvider configured so that React Router emits its hydration data.

Do NOT disable hydration.

The server should continue using the existing StaticRouterProvider.

Do NOT replace StaticRouterProvider with BrowserRouter.

Do NOT remove the hydration data.

==================================================
3. FIX THE HTML STRUCTURE
==================================================

The critical issue is that the HTML generated by StaticRouterProvider currently places React Router's hydration <script> inside:

<div id="root">
    ...
    <script>...</script>
</div>

The final prerendered HTML must instead have this structure:

<body>
    <div id="root">
        <!-- ONLY the React application markup -->
    </div>

    <!-- React Router hydration data/script must be OUTSIDE #root -->
</body>

The hydration script must NOT be a child of #root.

==================================================
4. MODIFY scripts/prerender.js
==================================================

Inspect how the output of renderToString() is currently inserted into the HTML template.

Do NOT simply remove the hydration script.

Instead, separate:

A. the React application markup

from:

B. the React Router hydration script/data emitted by StaticRouterProvider.

Then construct the final HTML so that:

<div id="root">
    React application markup only
</div>

and the React Router hydration script is placed immediately after #root, before </body>.

If the current renderToString() output contains the hydration script appended after the application markup, extract that script from the rendered output before inserting the application markup into #root.

Then append the extracted hydration script outside #root.

The resulting HTML must have only actual React application markup inside #root.

Do not hard-code or manually recreate React Router's hydration-data payload.

Use the hydration script/data produced by StaticRouterProvider itself.

==================================================
5. DO NOT CHANGE src/main.tsx HYDRATION ARCHITECTURE
==================================================

Keep:

hydrateRoot(...)

for prerendered pages.

Keep the existing:

window.__staticRouterHydrationData

consumption.

The browser router should continue using:

const hydrationData =
  (window as typeof window & {
    __staticRouterHydrationData?: unknown;
  }).__staticRouterHydrationData;

const router = createBrowserRouter(routeConfig, {
  ...(hydrationData ? { hydrationData } : {}),
});

Do NOT replace hydrateRoot() with createRoot().

Do NOT remove hydrationData.

==================================================
6. IMPORTANT: DO NOT HYDRATE THE SCRIPT
==================================================

The final HTML must ensure React does not see the React Router hydration <script> as part of the React application's #root DOM tree.

The client must hydrate only the application markup.

The hydration data must remain available globally through the script generated by StaticRouterProvider.
